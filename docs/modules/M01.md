## Interface `ghostlab-providers/1`

`src/ghostlab/providers/` needs the `service` extra, for httpx 0.28.1, which
was already locked by M00. Manifests are unchanged.

```python
adapter = adapter_for(ProviderConfig.from_env("meta_responses"))   # or an explicit ProviderConfig
reply: ModelReply = adapter.complete(request: ModelRequest, bundle: ContextBundle, cancel=None)
adapter.last_attempts   # [Attempt(status_code, error_code, duration_ms), ...] for telemetry
```

- **Contracts consumed:** M00 `model_request/1`, `context_bundle/1`,
  `tool_definition/1` and the registered output schemas (for example
  `experiment_proposal/1`).
- **Contract produced:** `model_reply/1`.
- **Adapters:** `MetaResponsesAdapter` (primary, `POST {base}/responses`) and
  `BasetenChatAdapter` (conditional, `POST {base}/chat/completions`). They are
  separate wire serializers with no shared wire code.
- **Raised before any network call:**
  - `ProviderConfigError`: a different provider or model than configured
    (there is no fallback and no silent switch), a missing key or model env
    variable, or a non-https base URL.
  - `ProviderRequestError`: a mismatched context bundle, an unknown schema
    version, unpaired tool results, a continuation from another adapter, or
    `max_output_tokens` below 16 on Meta.
- **Transport and provider failures** return `status="failed"` with a typed
  `ErrorInfo`. `side_effect` is always `"none"`, because a model call never
  dispatches tools.

### Behavior

| Concern | Rule |
| --- | --- |
| Context | Only trusted controller `instruction` items reach `instructions`/`system`, followed by a fixed data notice. Everything else is a JSON document in the user message, so untrusted text can't break out of its field. |
| Tool calls | Returned raw (`tool_name`, `arguments_json` unparsed) for M05/M06 to validate. Invalid arguments are not "fixed". Calls are exposed only with status `tool_calls`. A truncated (`length` / Meta `incomplete`) or filtered (`content_filter`) reply keeps its `incomplete`/`refused` status, and any calls in it are withheld from both the reply and the continuation, so they can never be answered or executed. |
| Pairing | Each tool result must answer exactly one pending call id. The pending ids travel in the adapter's opaque continuation and are checked locally before sending. |
| Continuation | Meta: `previous_response_id` plus pending call ids. Instructions are resent every turn, as the docs require. Baseten: the prior assistant/tool messages are carried in the token, because Chat Completions has no server state. Tokens are prefixed per adapter, so they can't cross providers. |
| Structured output | Responses `text.format` or Chat `response_format` json_schema. `strict` is set only when the schema meets Meta's strict subset. Replies are parsed and validated locally against the M00 model, and failures become `provider_invalid_output`. |
| Strict tools | `strict: true` only when the parameter schema meets the documented strict subset; otherwise `false`. |
| Usage | `input_tokens`/`output_tokens` (Meta) and `prompt_tokens`/`completion_tokens` (Baseten). Missing or malformed counts are `null`, never 0. Cost is always `null` (unknown). |
| Model echo | A response naming a different model fails as `provider_invalid_output` unless it is listed in `accepted_response_models`. |
| Retry | Only 429, 500, 502, 503 and connection errors. At most `max_attempts` (default 3, maximum 5). Exponential backoff (0.5 s base) plus jitter, with `Retry-After` honored up to a cap. No retry on other 4xx, on 504 (Meta says not to retry it unchanged) or on client timeouts. |
| Attempt gate | `Runtime.attempt_gate`, when set, is called before every outbound HTTP attempt, retries included. Returning `False` stops with `budget_exhausted` before sending. The probe uses it to cap paid attempts; M05 can use it to reserve each retry. |
| Deadline | `ModelRequest.timeout_ms` bounds all attempts, backoff and reading the body together. Backoff that would pass it stops early, and the deadline is checked between body chunks (`deadline_exceeded`). |
| Response size | Bodies are streamed with an incremental cap: success bodies over 4,000,000 bytes are rejected (`provider_invalid_output`) without downloading the rest, and a larger declared `Content-Length` is rejected before reading. Error bodies are cut at 65,536 bytes and read only for their message. |
| Cancellation | Any object with `is_set()`. It is checked before each attempt and during backoff. An in-flight HTTP request is not interrupted. |
| Secrets | A `Credential` never appears in repr, str or pickle. Provider error text is redacted (the key value and `Bearer`/`Api-Key` tokens). Every `ModelReply` is also scrubbed of the configured key in every field (error, text, tool arguments, structured output), covering HTTP-200 `failed` responses and echoed keys. Continuation state is masked **before** it is encoded, because the token is opaque to the reply scrub and Baseten resends its history on the next turn; an echoed key therefore never reaches a later request body. Meta keeps prior turns server-side (`previous_response_id`, `store: true`), so an echo there stays in the provider's retained state; that retention decision is M06/M09's. Keys are read only from the environment. |
| Streaming | Not implemented. `ModelRequest.stream` is fixed to `false`. |

## Documentation basis (fetched 2026-10-29)

| Source | Used for |
| --- | --- |
| [Meta Responses](https://dev.meta.ai/docs/protocols/responses) | Endpoint, Bearer auth, `instructions` resent per turn, `previous_response_id`, `function_call`/`function_call_output` with `call_id` (1–64 characters), `max_output_tokens` ≥ 16, status values, usage fields, `store` default `true` |
| [Meta tool calling](https://dev.meta.ai/docs/tool-calling) | Flat Responses tools and nested Chat tools, `strict` optional, every call answered before the next request, `tool_choice` `auto` only (not sent) |
| [Meta structured output](https://dev.meta.ai/docs/structured-output) | `text.format` (Responses), `response_format.json_schema` (Chat), the strict subset rules |
| [Meta error handling](https://dev.meta.ai/docs/error-handling) | Error body, the retry table (429/500/503 retry; 400–413 don't; 504 not unchanged), `Retry-After`, backoff guidance |
| [Baseten Chat Completions](https://docs.baseten.co/reference/inference-api/chat-completions) | Endpoint, Bearer auth, nested tools, `tool_calls`, `role: tool` + `tool_call_id`, `max_tokens`, `finish_reason` `stop`/`length`/`tool_calls`, usage fields and their possible absence |

Unverified until the authenticated probe runs:

- **Responses `text.format` layout:** the structured-output page doesn't spell
  out the `name`/`schema`/`strict` fields for Responses. They mirror the
  documented Chat `json_schema` object.
- **Responses `function_call` `name` and `arguments`:** described on the
  tool-calling page, but absent from the Responses output schema.
- **Baseten `message` vs `delta`:** the reference's examples read
  `choices[0].message`, while its schema names `delta`. Both are accepted.
- **Baseten `content_filter`:** this `finish_reason` (mapped to `refused`)
  is not in the documented list.
- **Model echo:** whether the response `model` equals the requested id.
- **Function-result errors:** there is no documented `is_error` flag on the
  wire, so `output_json` is sent verbatim and error details must be inside it.
- **Server-side storage:** Meta `store` defaults to `true`, and
  `previous_response_id` relies on it. Server-side retention of prompts is a
  privacy consideration for M06/M09.
- **Hackathon model ids:** `muse-spark-1.3`, Baseten
  `meta-models/muse-spark-open` and `-1026` access are unverified. No model
  id is defaulted anywhere; it must be configured explicitly.

### Probe: `scripts/probe_provider.py`

- **Dry run is the default:** it prints the plan, writes a report with
  `"live": false` and sends nothing.
- **Live mode** requires all of `--live`, an exact `--model`, `--max-calls`
  (1–10), `--confirm-paid-calls`, and the key in `MODEL_API_KEY` or
  `BASETEN_API_KEY`. Each call is capped at 512 output tokens.
- **`--max-calls` caps outbound HTTP attempts, retries included**, since each
  attempt may be billed. The report gives `calls_made` (model calls) and
  `http_attempts` separately; a check that needs more attempts than remain is
  skipped, and an attempt past the cap is never sent.
- **Checks:** `auth_minimal`, `tool_roundtrip` (2 calls, with tool results
  labeled synthetic fixtures), `continuation_after_tool_result`,
  `structured_proposal` and `usage_capture`. A check that would exceed the cap
  is reported `skipped_call_cap`.
- **Report:** written to `artifacts/local/compatibility-report.json`
  (git-ignored) and redacted. A run on a mock transport is labeled
  `"transport": "mock", "live": false`.
- It has **not** been run live. Live exploration stays disabled until someone
  with an authorized key and budget runs it and the report passes.

## Proposals and requests

- **To M05:** a cancellation and deadline handle. Adapters accept any object
  with `is_set()` and use `ModelRequest.timeout_ms` for the deadline. When M05
  publishes its handle, it should satisfy `is_set()` or M01 will adapt.
  `budget_reservation_id` is passed through untouched; reconciliation is M05's.
  `last_attempts` gives the retry count and timing. **Retries cost attempts:**
  M05 must reserve and account every HTTP attempt, not just each `complete`
  call, for example by supplying `Runtime.attempt_gate`.
- **To M00 (optional, no change made):** `ModelReply` has no field for attempt
  count, raw finish reason or reasoning-token usage. M09 telemetry can use
  `last_attempts` for now.
- **To M03:** `ContextBundle.prerequisite_refs` and `items[].artifact` are sent
  by id only. If the model needs artifact contents, M03 must inline them as
  items. The bundle `sha256` is not verified here, because no digest
  convention exists yet.

## Known gaps

- No authenticated call. Every live capability is untested.
- Streaming is not implemented. It needs its own partial-argument and
  interruption gate.
- An in-flight request can't be cancelled, only between attempts. A 504 or
  client timeout is final; Meta suggests background mode, which is not
  implemented.
- `store` uses Meta's default (`true`); a data-retention decision is pending.
  `reasoning.effort`, `temperature` and other optional parameters are not sent.
- The strict-subset check covers the documented rules only. Live acceptance of
  our Pydantic-generated schemas (`$defs`/`$ref`, `pattern`, `const`) is
  unverified.

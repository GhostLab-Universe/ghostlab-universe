1. What happened

One synthetic order for INR 2,500. The refund commits, the confirmation is lost to a timeout, and the vulnerable adapter retries without an idempotency key — refunding twice. The verifier catches it; the repaired adapter refunds once.

  1. Order placed. get_order returns ord_demo_001: 250000 paise, owner verified.

  2. Refund committed. issue_refund attempt 1 commits 250000 paise in the world.

  3. Confirmation lost. The agent receives a timeout even though the refund committed. The world and the agent now disagree.

  4. Naive retry. The vulnerable adapter retries issue_refund with no idempotency key. A second 250000 paise commits. Total: 500000 paise.

  5. Detected. The verifier flags duplicate_refund and total_refund_exceeded against the fork trace.

  6. Repaired. The repaired adapter retries with idempotency key refund-ord_demo_001-1. Total: 250000 paise — exactly once.

4. Decide the repair

The repair under review: retry with idempotency key refund-ord_demo_001-1, so a lost timeout can never commit twice. Review the consequence before deciding.

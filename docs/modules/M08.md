# M08 — Guided refund run: UI, developer guide, browser acceptance (Track D)

Status: **fixture-mode complete; service integration pending.** Base: `feature/m00-foundation`
(shared checkout; Track D ran in parallel with Tracks A/B/C). This module owns `web/src/`,
`web/public/`, `web/tests/`, `web/index.html`, `web/vite.config.ts`, `web/tsconfig.app.json`
and this guide. It does not edit backend packages, canonical schemas, manifests or lockfiles:
`web/package.json` is untouched (no new dependencies, no new scripts).

Prior capability/contract refs for this track arrived as gaps, so the build is grounded in
inspected repo sources instead: `src/ghostlab/core.py`, `src/ghostlab/capsule.py`,
`src/ghostlab/envs/*` return shapes, `schemas/v1/*`, `schemas/typescript/contracts.ts` and
`examples/contracts/**`. No M07 route contract is invented anywhere in this module.

## What was built

A 7-step guided flow over the synthetic INR refund world. Every step is a real route served
from the production bundle:

| Step | Route | Purpose |
| --- | --- | --- |
| 1 | `/guide/1-environment` | Select env, import + digest a v1 manifest |
| 2 | `/guide/2-qualification` | Inspect capabilities, qualification, env limits |
| 3 | `/guide/3-agent` | Select vulnerable/repaired adapter + operator note |
| 4 | `/guide/4-configure` | Fixture, faults, invariant focus, limits, objective |
| 5 | `/guide/5-review` | Effective config, provenance, derived payloads |
| 6 | `/guide/6-run` | Run, recorded config, evidence, Reality Diff |
| 7 | `/guide/7-export` | Export bundle, compare, retest |

`/` redirects to step 1; unknown routes render a NotFound screen. State is in-memory:
in-app navigation preserves it, full page loads reset to defaults (both covered by tests).

### One server-validated config

`web/src/config.ts` (pure, zero imports) defines `EffectiveConfig` plus the validation the UI
applies before running and the API client re-applies on submit — the same rules the service
will enforce. No displayed control is complete until its value reaches execution and is
recorded: each of the 20 `CONTROL_PATHS` renders in the step-5 provenance table, is echoed in
the step-6 recorded config, and ships in the step-7 export. The browser suite asserts this
chain for values it sets (25 tool calls, repaired adapter, edited objective, edited fixture,
removed invariant, imported digest).

Constraint sources (mirrored, never forked):

| Config area | Mirrors |
| --- | --- |
| fixture bounds, scenario bounds, adapter behavior | `src/ghostlab/core.py` |
| budget/objective/criteria bounds, payload shapes | `schemas/v1/campaign_spec.schema.json`, `budget_limits.schema.json`, `experiment_proposal.schema.json` |
| env id/version/tool/hook patterns, manifest v1 rules, canonical digest | `src/ghostlab/envs/registry.py`, `manifest.py` |
| rendered result/diff/capsule/finding types | `schemas/typescript/contracts.ts` (`RunResult`, `ExperimentResult`, `RealityDiff`, `CapsuleV1`, `InvariantFinding`) |

`toCampaignSpec`/`toExperimentProposal` map the config onto the frozen payload shapes; the
proposal text is derived deterministically from the config (no model output at this stage).

### Fixture tiers (never mixed silently)

- **Approved M00 fixtures** (`examples/contracts/**`, incl. `core/`): validated by
  `tests/contracts/test_contracts.py`. Rendered only beside
  "Approved M00 fixture: development aid, not evidence from this run."
- **Illustrative env fixtures** (`web/src/fixtures.ts` + `illustrative-manifest.json`):
  hand-shaped from the inspected Track A return shapes to preview UI states. Rendered only
  beside "Illustrative dev aid … never evidence."
- **Scripted runs**: step 6 records the submitted config but shows fixture results, labeled
  "Scripted run…". The frontend never computes financial verdicts; checks come from evidence.

`LiveExperimentApi` (`web/src/api.ts`) is a stub that throws instead of guessing M07 routes.
Wire it when M07 lands; `FixtureExperimentApi` stays for offline UI development.

## Commands (all executed 2026-11-02 on Windows 11, Node v22.14.0)

> Note: `web/package.json` engines ask for Node >=24.22.1 <25 (M00's supported set). The
> commands below also pass on the installed Node v22.14.0; that is an observation, not a
> support claim — M00 owns the engines range.

From the repository root unless noted:

```sh
# 1. Typecheck the guided UI (strict + exactOptionalPropertyTypes +
#    noUncheckedIndexedAccess). Exit 0.
web\node_modules\.bin\tsc -p web\tsconfig.app.json --noEmit

# 2. Config-core unit tests (stock Node type stripping; oracles are
#    node:crypto and a python-stdlib canonical-JSON one-liner). 16 pass.
node --experimental-strip-types --test web/tests/config.test.mjs

# 3. Production build (run with cwd=web). 34 modules, dist/ in ~0.4s.
#    (PowerShell: cd web; node node_modules/vite/bin/vite.js build)
node node_modules/vite/bin/vite.js build

# 4. Browser acceptance against web/dist (headless Chrome via CDP, stdlib
#    only; temp state under os.tmpdir()/track-d-accept-*, per-step PNGs).
#    46/46 checks pass, including a real `ghostlab replay` of the exported
#    capsule (reproduced: true, model_calls: 0).
node web/tests/acceptance.mjs

# 5. Existing workflows still pass (untouched by this module).
npm --prefix web run contracts:verify        # contracts.ts matches bundle
npm --prefix web run contracts:typecheck     # exit 0
$env:PYTHONPATH='src'; python -m unittest tests.test_core            # 14 OK
$env:PYTHONPATH='src'; python -m ghostlab replay examples/contracts/core/capsule_v1.refund_failure.json
# reproduced: true, model_calls: 0
```

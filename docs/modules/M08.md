# M08 — Interface

Campaign, evidence, Reality Diff, approval and capsule views over M07's published
contract. React, Vite and TypeScript; no other UI framework.

**Base:** `architecture-and-refund-core` at `24942bd`, with M00's
`feature/m00-web-tooling` at `5a69dac` merged in for the type packages, Playwright and
scripts. M04, M05, M06 and M07 are not in that base, so this branch consumes M07's
contract by copying it, not by merging it.

**Pinned:** M07's contract at `05cc16d` and M05's outcomes at `a785d86`.

**Status: complete except integrated acceptance.** Both flows run end to end in real
Chrome against unmerged M07 with scripted inference. Integrated acceptance on the
integration branch is blocked until M04, M05, M06 and M07 merge. Nothing here used a live
model or real payments.

## Running it

From `web/`:

```text
npm run typecheck                                strict check of src
./node_modules/.bin/tsc -p tsconfig.tests.json   strict check of src, tests and configs
npm run build                                    production build: talks to M07
npm run build -- --mode fixture                  test-data build
npm run dev -- --mode fixture                    interface over test data
npm run test                                     generated types, unit and render tests
npm run test:browser                             Chrome, against the fixture build
```

Against a service. `outcome_server.py` wraps M07's `tests/api/fixture_server.py` and adds
scripted replies that reach the unfinished outcomes. Inference stays scripted.

```text
GHOSTLAB_AUTH_MODE=local_dev python tests/integration/outcome_server.py \
    --m07 <checkout of feature/m07-api> --root <dir> --port 8788
GHOSTLAB_API_ORIGIN=http://127.0.0.1:8788 npm run dev
M07_ORIGIN=http://127.0.0.1:8788 node tests/integration/run.mjs
M08_BROWSER_MODE=service GHOSTLAB_API_ORIGIN=http://127.0.0.1:8788 npm run test:browser
```

`GHOSTLAB_API_ORIGIN` defaults to `http://127.0.0.1:8787`, M07's local server. M07 sends
no CORS headers and accepts loopback peers, hosts and origins only, so the browser reaches
it through this same-origin proxy.

Browser runs need Chrome, and use `channel: "chrome"`. `M08_BROWSER_OUT` holds builds,
results and screenshots, and `M08_BROWSER_PORT` sets the port. Point `TEMP` at the same
place to keep Chrome's profile out of the system temp folder.

The HTML entry is `web/src/index.html`, and Vite's root is `web/src`, because M08 owns
`web/src` and not `web/`. The TypeScript project is `tsconfig.app.json`, which the
`typecheck` script names.

## How it decides what to show

**Status comes only from an authoritative read.** `ExperimentEvent` has no status field
and its summary is untrusted text, so `logic/live.ts` never derives status from an event.
Each poll reads the campaign first, then any events `event_count` says exist. Every read
is numbered: a response older than the newest applied, or sent before the connection
dropped, is ignored, and a lower `event_count` is never applied over a higher one.
Reading resumes from the cursor, so a reconnect loses nothing and duplicates nothing.

**Success needs agreement.** `logic/repair.ts` shows success only if `verified` is true,
the outcome is `repair_verified`, `run_status` is `completed` and `safety_held` is true. A
`completed` campaign is shown as "Stopped: completed" in a neutral tone, because
`repair_rejected` and `failure_found_repair_pending` also end that way.
`repair_incomplete` is never success, at either status. Fields are shown as recorded,
and an unset `held_by` says why.

**Stopped early is not a pass.** `coverage_incomplete` is a warning in the campaign and
diff views, with each experiment's `coverage`. A truncated run says so in the evidence
view even when its checks pass. A violation seen before truncation stays visible and
still goes to approval. `logic/replay.ts` never reads `reproduced` as success: a replay
of a truncated run says so from `run_status`, and a reproduced failure stays a failure.

**A settings change is a block, not a failure.** `logic/failure.ts` keys on M07's
`settings_changed` reason, not its code. M07 uses that reason for three causes and only
restoring settings fixes one, so the copy says that and points at the message. The reason
can also come from capsule export, so the copy doesn't assume an approval exists.
`failed` / `settings_changed` is terminal, where `resume` does nothing, so it offers no
resume. An approved, unspent approval still explains itself after a reload.

**Redacted text is ordinary text.** `[REDACTED]` and `(secret-shaped text redacted)`
render as written. `secret_shaped_text` is a validation error with M07's reason.

**Nothing is computed that could read as a verdict.** Ledger totals and metrics are the
recorded ones. `logic/stateDiff.ts` compares two records to point at the evidence: at the
journey's first divergence the request and outcome match and only `sharing` and
`permission_timeline` differ. The page says it does not judge either side.
`logic/coverage.ts` falls back to the two run statuses only on an older checkpoint with
no coverage, and says so. A record claiming complete over an unfinished run reads as
incomplete.

**Approvals are bound.** `logic/approval.ts` builds the body from the request's id and
digest plus the decision and reason. There is no role, approver or scope field. Controls
follow the service's `effective_status`. After any decision the page re-reads the service.
Each exact body keeps one `Idempotency-Key`, so a retry can't decide twice. If the service
returns no action, the page says not to approve and the buttons stay disabled.

**Test data is structural.** Every result carries its origins. A fixture build always
shows a banner that can't be dismissed, and each section names its sources. A normal
build contains no fixture data. The header always shows `auth_mode`,
`production_authenticated` and `inference` as recorded, and scripted inference is called
out. Requests are same-origin, and the Content-Security-Policy limits `connect-src` to
the page's origin, so no credential or provider call exists in the browser.

**Narrow screens stack.** Below 680px each table row becomes a name with two labelled
values, because every table has that shape. Horizontal scrolling put the values off-screen.

## Gaps

- `configured_tokens` can't work from a browser, because this UI holds no credentials.
  `local_dev` is the only session a browser can use today.
- M07 has no campaign or approval list, so campaigns open by id and the URL is the only
  memory of one.
- `importCapsule` and replay by id are not surfaced. M05 emits neither `capsule_exported`
  nor `replay_completed`, so capsule actions never appear in events.
- `failed` / `repair_incomplete` is fixture-only here, because one server has one world
  fixture. M07's `test_m07_outcomes.py` covers it. `repair_did_not_hold` has presenter tests
  only: nothing records it.
- Stacked rows use `display: grid`, which can remove table semantics for assistive
  technology on narrow screens. No screen reader has been tried.
- Polling is the event transport, so a tool event appears up to 2 seconds late.

## Rejected

- **Reading status from `campaign_status_changed` events.** They carry no status field,
  and parsing an untrusted summary would let text change what is shown.
- **Hand-written coverage, repair or replay types.** M07 published them, and a brief
  stopgap for `coverage` was deleted when it did.
- **A second `RealityDiff` view for refund.** M07 maps refund onto the world contracts.
- **Disabling Approve by the browser's clock.** `effective_status` is the service's.
- **Fixtures in the production bundle.** They would be excluded by care, not construction.
- **Horizontal scrolling for narrow tables.** It hid the values the page exists to show.
- **A Resume button on `failed` / `settings_changed`.** The service does nothing with it.

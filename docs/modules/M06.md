# M06 — Policy, security and approvals

Policy version **`policy-1`**. Branch `feature/m06-policy-security`.

This branch stacks on the M04 interface commit `1359c53`, which sits on
integration `6554cff`. It consumes:

- M00 `ghostlab-contracts/1`: `TrustedScope`, `Principal`, `ToolCall`,
  `ProposedToolCall`, the approval contracts, `BudgetLimits` and `ErrorInfo`;
- M04 `ghostlab-storage/1`: the `ApprovalStore` protocol only.

M06 **decides**. It does not execute tools (M02), account budgets (M05),
persist (M04) or expose routes (M07).

## Threat and boundary map

| Threat | Boundary | Where |
| --- | --- | --- |
| Model output or tool arguments claim an identity | `customer_id` must equal the controller's `PrincipalBinding` for the session principal; otherwise `identity_mismatch` or `unbound_principal` | `policy/authorization.py` |
| Model proposes an unknown tool or malformed arguments | Allowlist, then strict typed parse; NaN, bool and float amounts and extra fields are rejected | `parse_proposed_call` |
| Crafted or over-wide scope | Per-role tool ceiling applied on every call, even when the scope lists more | `ROLE_TOOL_CEILINGS` |
| Delegated privilege escalation | Only an undelegated supervisor delegates. A child gets at most parent ∩ role ceiling, is never a supervisor and cannot re-delegate | `delegate` |
| Workers inheriting supervisor authority | `delegate`, `write_memory` and `export_capsule` are supervisor-only and never delegated; every worker's capability set is a strict subset | `ROLE_CAPABILITIES` |
| Cross-project access | Every decision checks `scope.project_id`; isolation helpers raise | `authorize_*`, `security/isolation.py` |
| Stale policy | Scopes, approvals and decisions carry `policy_version`; any mismatch is denied | all |
| Approval replay, change or expiry | The digest binds the exact action; decisions are pending-only; consumption is single use and checked before expiry | `policy/approvals.py` |
| Model or automation approving itself | Approvers come from the session; `service` principals never approve; `local_dev` only in local-dev mode | `ApprovalService.decide` |
| A human approving in a project they have no authority over | An injected `ApproverAuthority` must authorize the principal for that project before the approval is even looked up; an approval id or action digest is not authority | `ApprovalService.decide` |
| Secrets in logs, errors or traces | `Redactor` (env literals, bearer/basic tokens, `sk-…`, `key=value`, secret-named keys) and `RedactingFilter` for logging | `security/redaction.py` |
| Local dev mistaken for production | Explicit `GHOSTLAB_AUTH_MODE=local_dev`, loopback bind only, refused when `GHOSTLAB_DEPLOYMENT` isn't `local`; `is_production_authenticated` is always false | `security/local_dev.py` |
| Unknown or uploaded code | Disabled. The trusted local backend runs checked-in adapters only. An isolated backend additionally needs evidence for all six checks plus an explicit enable | `policy/execution.py` |

The synthetic refund world deliberately allows cumulative over-refunds so the
verifier can find them. That is business behaviour under test. None of the
boundaries above are relaxed for it.

## World-aware authorization (`policy/world.py`, 2026-10-30)

This is additive to `policy-1`; the refund tool policy is unchanged. It holds two
kinds of rule apart.

**Boundaries apply to every run of every world, in every mode:**

| Check | Function | Denial |
| --- | --- | --- |
| The world is implemented (`is_executable`) | `authorize_world` | `world_not_runnable` |
| The scope's project and policy version | `authorize_world_tool` | `cross_project`, `unknown_policy` |
| The tool and arguments match the reviewed pack | `authorize_world_tool` | `unknown_tool`, `invalid_arguments` |
| The tool is in the scope, and its effect is within the role's ceiling | `authorize_world_tool` | `tool_not_in_scope`, `tool_not_in_role_ceiling` |
| The principal has a bound identity in this project and world | `authorize_world_tool` | `unbound_principal` |
| Only the bound owner changes the world | `authorize_world_tool` | `identity_mismatch` |

Role ceilings follow each tool's declared `effect`, so a new pack needs no
tool-name list here. `WorldActorBinding` supplies the identity, and the owner comes
from the controller's fixture. A tool argument can't set identity: where a pack's
tool names one, as refund's `customer_id` does, it must equal the bound identity.

**Business rules under test may relax only for an experiment.**
`execution_mode_for(purpose)` is the single source of that choice:

| Purpose | Mode | Guard |
| --- | --- | --- |
| `experiment` (baseline and faulted runs) | `lab` | off, so the verifier can find the failure |
| `repair`, `operation`, or anything else | `enforced` | on |

This module only decides; the wiring is in M05 (PR #17), which calls this function
from its own code, records the resulting `ExecutionMode` with the evidence, and sets
the world's `guarded` flag from it. M05 must also name the mode in the approved
action, because `ApprovalService` binds whatever action it is given and doesn't
require one. No proposal can express enforcement, because strict contract validation
rejects any such field.

**Delivery.** `authorize_delivery` decides from the recipient's permission read
*inside* the tool call, after pending revocations apply and before delivery
changes state. A check made before the call can't close the check-to-delivery race,
because the revocation applies during the call. It also requires a world scope that
can itself deliver, in a runnable world: the right project alone isn't enough.

**Approvals.** `ApprovalRequest.scope` is a `TrustedScope`, whose tool names are
refund-only. `supervisor_scope` is a world-neutral supervisor scope with no tools,
which M00 documents as valid. The approval is bound to its world through the action
digest. No contract change is needed.

## Interfaces (`policy-1`)

- `authorize_tool(scope, call, *, project_id, binding) -> Decision`
- `authorize_proposed_call(scope, proposed, *, project_id, binding)`, which
  returns a `Decision` and the typed call (or `None` when denied)
- `authorize_capability(scope, capability, *, project_id) -> Decision`
- `enforce(decision, action)` runs `action` only when allowed, and otherwise
  raises `PolicyDenied`. Denial performs no call.
- `Decision(allowed, code, reason, policy_version)`, with `.error_info()`
  giving an M00 `ErrorInfo` (`forbidden` or `validation_failed`,
  `side_effect: none`)
- `root_scope(project_id, principal)` and `delegate(parent, role, tools)`
- `PrincipalBinding.customer_id_for(project_id, principal)`, with
  `StaticPrincipalBinding` for the synthetic world
- `ceiling_for(role)` and `check_within_ceiling(role, limits)`
- `ApprovalService(store, *, approvers, local_dev_mode)` with `.request(...)`,
  `.decide(session_principal=..., project_id=..., submission=..., ...)` and
  `.consume(project_id=..., approval_id=..., action=..., now=...)`;
  `action_digest(action)`
- `ApproverAuthority` protocol (`may_approve(principal, project_id)`), with
  `ProjectApproverAllowlist({project_id: {principal_id, ...}})` as the
  explicit, deny-by-default local-MVP implementation. It is required:
  `ApprovalService` refuses to start without one.
- `authorize_execution(origin, backend, *, qualification, unknown_code_enabled)`
- `Redactor`, `RedactingFilter`, `require_local_dev`, `require_same_project`

Role tables are read-only mappings:

| Role | Tools | Capabilities |
| --- | --- | --- |
| supervisor | all three | delegate, write_memory, read_memory, read_evidence, request_approval, export_capsule |
| target | all three | none |
| analyst | get_order, get_refund_status | read_memory, read_evidence, request_approval |
| explorer, worldsmith | none | read_memory, read_evidence |
| verifier | none | read_evidence |

Budget ceilings (`ROLE_BUDGET_CEILINGS`) are conservative defaults, not
measurements:

- **supervisor, campaign-level:** 50 model calls, 200 tool calls, 500k/50k
  tokens, 30 minutes, 2 parallel runs;
- **worker tasks:** smaller limits each;
- **verifier:** zero model and tool calls.

Cost ceilings are unset because no provider price is verified, so M05 must
record unknown cost as unknown.

## Approval lifecycle

```text
request (pending) ──decide(approve)──▶ approved ──consume(action)──▶ consumed
   │                └─decide(reject)──▶ rejected
   └─ decide after expires_at ─▶ expired
```

- **request:** requires the `request_approval` capability. The digest is
  sha256 of the canonical JSON action, also pinned on the payload ref. TTL is
  bounded (0 < ttl ≤ 24 h). The request records its scope and policy version.
- **decide:** the approver is the session principal. It first requires an
  allowed principal kind (no `service`; `local_dev` only in local-dev mode) and
  project approval authority from the injected `ApproverAuthority`, denying
  `approver_not_authorized` before any lookup. It then fails on non-pending,
  expired (which also marks the request `expired`), digest mismatch or policy
  change.
  It is recorded atomically through `ApprovalStore.record_decision`.
- **consume:** recomputes the digest from the action actually about to run.
  A changed action needs a new approval. It also requires `approved`, not
  expired and the same policy. It is atomic and single use through
  `ApprovalStore.consume`.

## Integration notes

- **M02:** call `authorize_proposed_call` or `authorize_tool` before dispatch,
  and only dispatch through `enforce`. Bind the world's actor from
  `PrincipalBinding`, never from arguments. `authorize_execution` gates
  `ExecutionBackend`. **This boundary is defined and tested, but not wired
  into `ghostlab.core`**, which M02 owns.
- **M05:** take ceilings from `ceiling_for`. Pause on `awaiting_approval` and
  resume only after `ApprovalService.consume` succeeds for the exact action.
- **M07 caller contract for approvals:**
  - `session_principal` is the authenticated session's principal, and
    `project_id` is the session's active project. Neither comes from the
    request body or URL alone.
  - Construct `ApprovalService` with an `ApproverAuthority` backed by trusted
    project membership. For the local MVP that is a `ProjectApproverAllowlist`
    configured by the operator (for example, the project owner).
  - Pass only the `ApprovalSubmission` body to `decide`; never a
    client-supplied approver or project.
  - Map `approver_not_authorized` and `approver_not_allowed` to 403. Map
    `not_found` to 404 only for an authorized approver, since unauthorized
    callers are denied before lookup.
  - Also: `require_local_dev` at startup in local mode, map
    `Decision.error_info()` and the other `ApprovalDenied.code` values to HTTP
    errors, and attach `RedactingFilter` to the service loggers.
- **M04:** `SqliteApprovalStore` must honour `ghostlab-storage/1`. M06's tests
  use a lock-guarded in-memory fake with the same semantics; running these
  tests against the SQLite store is an integration step after M04 merges.

NeMo Guardrails and OpenShell are optional, separately qualified adapters. No
trigger has been met, nothing was added, and neither replaces authorization or
the verifier.

## Gaps and requests

- No production authentication. `is_production_authenticated` is always false.
- Not wired into the core (M02), the orchestrator (M05) or routes (M07) yet.
- The committed approval tests run against a lock-guarded fake store. The
  coordinator's scratch run passed the same suite against M04's
  `SqliteApprovalStore`; a committed cross-store test belongs in M09.
- Project approval authority is an operator-configured allowlist for the local
  MVP. Membership-backed authority arrives with M07 sessions and production
  authentication.
- Separation of duties is not enforced: the campaign owner may approve their
  own campaign's action, as the single-user local MVP needs. Add a rule when
  multi-user projects exist.
- Redaction is pattern-based and can miss novel secret formats. It is defence
  in depth; keys must still never enter prompts, capsules or logs.
- **Request to M00 (non-blocking):** none for v1. A future `PolicyDecision`
  contract would let M09 record denials as typed events.

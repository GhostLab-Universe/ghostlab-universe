# M04 — Memory and persistence

## Published interface: `ghostlab-storage/1`

Defined in `src/ghostlab/storage/interfaces.py`. It is published first so M03
and M06 can build against one definition. It is frozen for this wave: a change
means updating this commit and rebasing the consumers, never silent drift.

| Interface | Consumer | Operations |
| --- | --- | --- |
| `MemoryStore` | M03 | `put`, `get`, `query` (scoped, effective-time and retention aware), `transition` (CAS) |
| `ApprovalStore` | M06 | `create`, `get`, `get_decision`, `record_decision` (pending → approved/rejected, digest-checked), `mark_expired`, `consume` (approved → consumed, single use) |

The interfaces follow these rules:

- **Isolation:** every call is scoped to a project taken from `TrustedScope` or
  the approval's scope. A named project that doesn't match the scope raises
  `ScopeViolation`. Another project's record reads as `NotFound`, so its
  existence isn't disclosed.
- **No policy:** stores apply atomic compare-and-set transitions. M06 decides
  approval validity and expiry, and M03 decides relevance.
- **Errors:** `StorageError`, plus `NotFound`, `ScopeViolation`, `Conflict` and
  `IntegrityError`. Messages never include record content.
- Records are M00 `ghostlab-contracts/1` models. Updated records are
  re-validated, so a transition can't bypass contract rules (for example,
  untrusted provenance can't become `verified`).

Budget reservations, artifact bytes and the workflow checkpoint saver are part
of M04's implementation for M05 and are documented below.

## Implementation

Base: `architecture-and-refund-core` at `6554cff` (M00 merged), interface
commit `1359c53`. Everything uses the standard library `sqlite3` plus Pydantic
contracts. The checkpoint saver is the only use of `langgraph-checkpoint-sqlite`
(the `orchestration` extra). There is no ORM, Redis or vector store, and no
manifest or lock change.

| Module | What it provides |
| --- | --- |
| `storage/memory_store.py` | `SqliteMemoryStore`, which implements `MemoryStore`, plus `due_for_expiry` and `purge_expired` |
| `storage/approval_store.py` | `SqliteApprovalStore`, which implements `ApprovalStore` |
| `storage/budgets.py` | `BudgetLedger` protocol (`ghostlab-storage-budgets/1`) and `SqliteBudgetLedger` |
| `storage/artifacts.py` | `ArtifactStore` protocol (`ghostlab-storage-artifacts/2`), `FileArtifactStore` and the project-owned `ProjectArtifacts` view |
| `storage/checkpoints.py` | `graph_checkpointer(graph_db, app_db=...)`, a LangGraph `SqliteSaver` in its own file |
| `storage/database.py` | `StoragePaths` (`ghostlab.sqlite`, `graph-checkpoints.sqlite`, `artifacts/`) and `open_database` |
| `storage/migrations.py` | Checksummed, forward-only migration runner |
| `memory/pipeline.py` | `MemoryPipeline`: capture, filter, normalize, store, retrieve, supersede, contradict, expire |

### Concurrency and transactions

These apply to a single local coordinator only.

- Every operation opens and closes its own connection, so a store can be shared
  across threads.
- The database runs in WAL mode.
- Writes run under `BEGIN IMMEDIATE`, so the write lock is held before the read
  that a compare-and-set depends on. Other writers wait for the 10 s busy
  timeout, then fail with `StorageError`. Nothing is silently overwritten.
- All checks and writes happen in one transaction: approval decision and
  consume, memory transition, and budget reservation (the sum and insert).
  Any exception rolls the transaction back.

### Rules the stores enforce

- **Isolation:**
  - Primary keys are `(project_id, id)` for memory and approvals, so the same
    id in two projects is two records.
  - Another project's record reads as `NotFound`. A mismatched project raises
    `ScopeViolation`.
  - Budgets and artifacts are keyed by campaign and artifact id. Their project
    authorization belongs to M06/M07; see the gaps below.
- **Re-validation:**
  - Every read re-validates the stored JSON, so a tampered row fails as
    `IntegrityError`.
  - Every update re-validates a modified dump. `model_copy(update=...)` is
    never used.
  - A memory transition the contract forbids raises `Conflict`. Untrusted
    provenance moving to `verified` is one example.
- **Approvals:**
  - Only `pending` requests are stored.
  - A decision must match the stored `action_digest`, and `new_status` must
    match the decision.
  - `consume` moves `approved` to `consumed` exactly once, with the digest
    checked.
  - Expiry and validity are decided by M06 before it calls the store.
- **Budgets:**
  - Committed usage counts open reservations at their full amount and
    reconciled ones at their actual.
  - A reconciled reservation with unknown actual keeps counting its full
    amount and is reported in the unknown count.
  - Overspend (actual greater than reserved) is recorded, not hidden.
  - The ceiling comes from the caller (M05, with M06 ceilings).
- **Artifacts:**
  - Bytes are stored content-addressed at `artifacts/sha256/<aa>/<digest>`,
    written to a temp file and renamed into place.
  - Metadata is an M00 `ArtifactRef`.
  - Reads are bounded and check that the stored metadata, size and digest
    match. Missing or altered bytes raise `IntegrityError`.
- **Graph checkpoints:**
  - They live in a separate file and refuse to share the application database.
  - They are workflow state only, never world snapshots or capsule replay.
- **Memory pipeline:**
  - Status comes from provenance. Content from a tool result, model output or
    memory starts `unverified`; only verifier, controller or human sources
    with evidence start `verified`.
  - Capture is idempotent (deterministic ids) and normalizes text (NFC,
    whitespace, control characters, 8,000 characters maximum).
  - Supersede keeps the history. Contradicted records stay queryable.
  - Expiry skips audit holds. `purge_expired` never deletes audit-policy,
    audit-hold or still-referenced records.

### Schema and migration policy

- Migrations live in `migrations/NNNN_name.sql`: contiguous, forward-only,
  checksummed in `schema_migrations`.
- Each migration runs in one transaction with its version row, and a failure
  rolls back.
- An edited applied migration, or a database newer than the code, is refused
  with `IntegrityError`.
- Downgrades are unsupported; add a new migration instead.
- `0001` creates memory and approvals. `0002` adds budgets, artifacts and the
  memory index. A test confirms that data written at v1 survives the upgrade.

### Unsupported deployment modes

- Multiple worker processes or hosts, and network file systems. Postgres is
  the later deployed store; the protocols are the port.
- Committing, syncing or sharing a live SQLite file. Each developer keeps a
  local database (`GHOSTLAB_SQLITE_PATH`, under the git-ignored `artifacts/local/`).
- Loading migrations from an installed wheel: the runner reads the repository's
  `migrations/` folder.

## World-aware persistence (2026-10-30)

This extension supports world-aware campaigns. It changes no M00 contract.

**Memory.** `ghostlab-storage/1` gains world records additively, on the same
table. `put` also takes `WorldMemoryRecord`, and `query` also takes
`WorldMemoryQuery`. The `world_version` column was already free text, so memory
needs no migration.

- Refund rows still load as plain `MemoryRecord`, so refund callers are unchanged.
- Other worlds load as `WorldMemoryRecord`, chosen from the row's column.
- A body that names a different world than its column fails as `IntegrityError`.
- `MemoryPipeline.capture` builds the record type for the observation's world. The
  world is part of the deterministic record id, so equal text in two worlds gives
  two records.
- Every query stays inside the caller's project. `world_version=None` still means
  any world, and each returned record carries its own `world_version`.
- `supersede` refuses a replacement from another world, and refuses to retire a
  verified record with unverified input.

**Artifacts.** A prefix can't enforce ownership, so `ghostlab-storage-artifacts/2`
adds one. Migration `0003` adds a nullable `project_id` column.
`FileArtifactStore.for_project(scope)` returns a `ProjectArtifacts` view bound to a
controller-issued `TrustedScope`:

- `put` records the owning project and namespaces the id with a digest of the
  project id. A plain prefix would collide: `a:b` + `c` and `a` + `b:c` join to the
  same string.
- `ref` and `read` filter on the owner column. Another project's artifact reads as
  `NotFound`, even to a caller holding its full reference. The namespace only keeps
  ids apart; the column is what enforces ownership.
- Blobs stay content-addressed, so identical bytes share one file. Ownership lives
  in the metadata row.
- The unscoped `ref` and `read` see only ownerless rows and refuse namespaced ids, so
  they can't reach a project's artifacts even if a row's owner column is edited.
- Unscoped `put` still writes an ownerless row but refuses a namespaced id, so it can't
  squat a project's name. Controllers must use the view (M05 does); M07 must not expose
  the unscoped API.
- An edited owner column fails as `IntegrityError` through a view, because the id's
  namespace no longer matches. Memory rows likewise fail if their columns and body
  disagree on world, project or record id.
- A damaged shared blob is rewritten by the next `put` of those bytes.

## Validation (2026-10-29, Windows 11, CPython 3.13.18)

`tests/storage/` has 50 tests, all using temporary directories:

- restart recovery for memory, approvals, budgets and graph checkpoints;
- project isolation;
- selective retrieval: kinds, statuses, world, campaign, effective window,
  retention, fractional-second ordering and limit;
- compare-and-set conflicts;
- untrusted memory can't be verified in place;
- tampered rows;
- contention: 40 concurrent puts lose nothing; of 16 racing transitions,
  16 consumers or 16 deciders, exactly one wins; 24 racing reservations
  against a ceiling of 5 produce exactly 5;
- budget accounting with unknown actuals and overspend;
- artifact roundtrip, dedup, corruption, missing bytes, forged refs and size
  bounds;
- migrations: upgrade with data preserved, rerun, edited migration, newer
  database, rollback of a failed migration, bad file names.

Results:
- **Full suite:** 440 passed (390 baseline + 50).
- **`python -m unittest discover -s tests`:** 14 OK.
- **`export --check`:** no drift.

## Known gaps

- **Budgets and artifacts are not project-scoped in the store.** M00's
  `BudgetReservation` and `ArtifactRef` carry no project. M06/M07 must
  authorize campaign and artifact access before calling the store. If a
  project column is wanted in the contracts, propose it to M00.
- **`due_for_expiry` and `purge_expired` are not in `ghostlab-storage/1`.** They
  are concrete `SqliteMemoryStore` methods used by the pipeline. Promote them
  into the interface in a later version if another store needs them.
- **Thread contention only.** Multi-process contention is untested.
- **Postgres repositories are not implemented.** They are the next deployment
  milestone.
- **M05 is not started.** It hasn't consumed the budget ledger or checkpointer
  yet, so their protocols may need a v2 once it does.

## Known limits after review

These were reported by the independent reviewer and left open on purpose. None is
reachable from a shipped path.

- A row written before migration 0003 whose id already looks like a project namespace
  (`<16 hex>.name`) stays intact but can't be reached by `ref`.
- A project-view name of 112 characters or more raises a raw validation error, because
  the namespace takes 17 of the 128 allowed characters.
- Concurrent `open_database` calls on a brand-new path can raise `database is locked`
  from `enable_wal`. Startup is a single process today.
- `Observation.supersedes` passed straight to `capture` isn't checked for world or
  verification status, and production code doesn't pass it. `supersede` refuses extra
  ids, so a record it writes names only the record it retired.
- `supersede` is two transactions. A failure between them leaves a live replacement
  that names a record which wasn't retired, and repeating the call converges. No
  shipped code calls it yet.
- `capture` raises `Conflict` when the same content already exists with different
  provenance, evidence, lineage or retention, rather than returning that other record.
- A stored body that isn't valid UTF-8 fails closed as `sqlite3.OperationalError`, not
  `IntegrityError`.

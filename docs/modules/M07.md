# M07 — Authenticated control plane

Interface published: `ghostlab-api/1` (`src/ghostlab/api/`).

Base: `feature/m05-world-campaigns` at `4501fa4` (PR #17, under fix). The integration
branch `architecture-and-refund-core` at `24942bd` doesn't yet contain the world-aware
stack (#14 M04, #15 M06, #16 M03, #17 M05). Contract-first development against those
unmerged PRs was explicitly authorized.

It consumes these interfaces:

| Interface | From | Used for |
| --- | --- | --- |
| `ghostlab-contracts/1.1` | M00 | Every record, run, diff, finding, approval, event and error |
| `ghostlab-orchestration/2` | M05 | `CampaignController`: start, resume, recover, state, record, capsules |
| `policy-1` | M06 | `ApprovalService`, `authorize_world`, `authorize_capability`, `ApproverAuthority`, `require_local_dev` |
| `ghostlab-storage-artifacts/2`, `ghostlab-storage/1` | M04 | `FileArtifactStore.for_project`, `ApprovalStore`, `graph_checkpointer` |

M07 owns HTTP and session adapters. It has no scheduler, no decision logic and no
database of its own, and it reimplements no simulation.

## Endpoints

`src/ghostlab/api/openapi.v1.json` is the contract. Regenerate it with
`python -m ghostlab.api.openapi`; `--check` and a test fail on drift.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/v1/session` | Principal, project, auth mode and inference mode resolved by the server |
| POST | `/v1/campaigns` | Create a campaign (`Idempotency-Key` required) |
| GET | `/v1/campaigns/{campaign_id}` | Authoritative status; use after any reconnect |
| GET | `/v1/campaigns/{campaign_id}/events` | Poll application events (`after`, `limit` ≤ 200) |
| POST | `/v1/campaigns/{campaign_id}/cancel` | Cancel a running or stalled campaign |
| POST | `/v1/campaigns/{campaign_id}/resume` | Owner: re-check a paused campaign or continue a stalled one |
| GET | `/v1/campaigns/{campaign_id}/experiments/{experiment_id}` | Proposal, diff, findings |
| GET | `/v1/campaigns/{campaign_id}/experiments/{experiment_id}/diff` | Reality Diff |
| GET | `/v1/campaigns/{campaign_id}/experiments/{experiment_id}/runs/{run}` | Inspect `baseline`, `fork` or `repaired` |
| POST | `/v1/campaigns/{campaign_id}/experiments/{experiment_id}/capsules/{run}` | Export a capsule |
| POST | `/v1/campaigns/{campaign_id}/experiments/{experiment_id}/capsules/{run}/replay` | Replay an exported capsule |
| POST | `/v1/capsules/import` | Validate, replay and store a `CapsuleV1` or `CapsuleV2` |
| POST | `/v1/capsules/{capsule_id}/replay` | Replay any capsule in this project (`capsule_id` is its artifact id) |
| GET | `/v1/artifacts/{artifact_id}` | Download a project artifact |
| GET | `/v1/approvals/{approval_id}` | Request, effective status, bound action, decision |
| POST | `/v1/approvals/{approval_id}/decision` | Approve or reject (`Idempotency-Key` required) |

There are no unauthenticated routes, including documentation: `docs_url`, `redoc_url`
and `openapi_url` are off.

**Shapes.** Responses compose M00 contracts. Refund evidence is mapped through
`ghostlab.contracts.world_refund`, so `WorldCampaignRecord`, `WorldRunResult`,
`WorldRealityDiff` and `WorldInvariantFinding` describe both worlds. A create body is a
`WorldCampaignSpec`, a decision body an `ApprovalSubmission`. `SessionInfo`,
`CampaignView`, `EventPage`, `ExperimentView`, `RunView`, `CapsuleInfo`, `ReplayResult`,
`ApprovalView` and `DecisionResult` are thin M07 views. `ReplayResult` and `RepairView`
have no M00 contract yet (see requests below).

**Errors.** Every non-2xx body is `ErrorResponse`: an M00 `ErrorInfo` plus `reason`, a
stable code finer than `error.code`.

| Status | `error.code` | `reason` examples |
| --- | --- | --- |
| 401 | `unauthenticated` | |
| 403 | `forbidden` | `world_not_runnable`, `capability_denied`, `inference_not_authorized`, `approver_not_authorized`, `approver_not_allowed`, `not_loopback` |
| 404 | `not_found` | absent, or owned by someone else: identical bodies |
| 409 | `conflict` | `settings_changed`, `idempotency_key_reused`, `awaiting_approval`, `campaign_finished` |
| 409 | `approval_invalid` | `digest_mismatch`, `not_pending`, `expired`, `policy_changed` |
| 413 | `validation_failed` | `too_large` |
| 422 | `validation_failed` | `invalid_request`, `capsule_invalid`, `not_a_capsule` |
| 429 | `rate_limited` | `too_many_campaigns`, with `Retry-After` |
| 500 | `internal` | generic text; detail goes only to the filtered log |

A validation error reports where and how a request failed, never the input.

## Authentication

**No production authentication exists.** `is_production_authenticated` is false for
everything, and `/v1/session` always says `production_authenticated: false`.

| Adapter | `auth_mode` | Use |
| --- | --- | --- |
| `LocalDevSessions` | `local_dev` | M06's explicit mode: `GHOSTLAB_AUTH_MODE=local_dev`, `require_local_dev` at startup, one principal of kind `local_dev` |
| `TokenSessions` | `configured_tokens` | Operator-configured bearer tokens, so more than one identity can be exercised on one machine. Only digests are kept |

Rules that hold for both, because neither is production authentication:

- `create_app` refuses `GHOSTLAB_DEPLOYMENT` other than `local`, and a non-loopback bind.
- Every request must come from a loopback peer, with a loopback `Host` and, if present,
  a loopback `Origin`. That stops another site or a rebound DNS name from driving a
  server on `127.0.0.1`. There are no CORS headers: a browser interface reaches the API
  through a same-origin dev proxy.
- `RequestGuard` runs before routing, so a route can't be left open by forgetting a
  dependency, and a request is authenticated before its body is read or parsed.

A session resolves on the server to one principal in one project. No path, query,
header or body names a project, principal, role or scope, and the bodies forbid extra
fields. A real adapter only has to implement `SessionAdapter.authenticate`, plus
whatever replaces the loopback rule.

**Identity to world binding.** `PrincipalBinding` and `WorldActorBinding` are
trusted-host wiring in `ApiConfig.services`. `ghostlab.api.local` binds the local-dev
principal to the synthetic customer and organizer.

## Authorization

| Resource | Rule | Enforced by |
| --- | --- | --- |
| Campaigns and their evidence | Owning principal in the session's project | `CampaignController._check_owner`, on every call. Anyone else gets a 404 |
| Artifacts and capsules | Any session in the project with `read_evidence` | `authorize_capability`, then `FileArtifactStore.for_project`. The unscoped API and M05's legacy fallback are not used |
| Approvals, read | Campaign owner, or an `ApproverAuthority` approver | `ControlPlane.approval` |
| Approvals, decide | `ApprovalService.decide`, with the session as approver | M06. `approver_not_*` is a 403 before any lookup; `not_found` is a 404 for an authorized approver |

A reviewer doesn't own the campaign, so campaign routes read as absent for them. They
can read the approval's summary, risks and exact action (the digest is recomputed before
it is shown), and download the run named by `request.payload`, which is a project
artifact.

## Request identity

Identity is derived, not stored, so it survives a restart and M07 needs no table.

- **Create.** `campaign_id` is `c-` plus a digest of project, principal and
  `Idempotency-Key`. A retry finds the checkpoint and returns the **current** campaign
  with `Idempotency-Replayed: true`. A different spec under the same key is a 409. Two
  sessions' keys can't collide. Concurrent duplicates join one worker: 8 at once start 1
  campaign and send 1 model request.
- **Decide.** `decision_id` is `d-` plus a digest of project, principal, approval and key.
  A retry returns the recorded decision; a different decision under that key is a 409.
  A second key meets `not_pending`.
- **Capsules** are content-addressed, so export and import need no key.
- **Cancel and resume** are idempotent by state.

## Execution

`start` and `resume` are synchronous, so each moving campaign has one daemon thread
(`jobs.py`) until it pauses or finishes. It isn't a scheduler: there is no queue,
ordering or retry, and order and budgets stay with M05's graph. At most
`max_active_campaigns` (default 4) run at once. One saver is shared; `SqliteSaver`
serializes its connection under a lock.

**The first step.** A route waits until the controller enters its first node, or raises.
`Services.on_node` is the signal. So the controller's own gates (world, ceiling,
inference) raise a typed error to the caller with nothing stored, and a campaign is
readable the moment its id is returned.

**A decision resumes the campaign under its owner.** The owner comes from the approval
record, which the controller wrote from its own session. A decision can land between
the campaign reporting `awaiting_approval` and its worker reaching the pause, so the
resume then follows that worker rather than being lost. Resuming authorizes nothing:
only a stored approval and a single-use `consume` run a repair.

**Status.** `record.status` comes from the checkpoint's own status, not `record()`, which
reports any unfinished graph as `awaiting_approval`. `job.state` sits beside it:

| `job.state` | Meaning |
| --- | --- |
| `active` | A worker is running it |
| `idle` | Paused or finished |
| `stalled` | Unfinished, with no worker: a crash, restart or worker error. `job.error` holds a sanitized cause when this process saw it. `resume` continues it |

**Cancel** sets the `threading.Event` given to the controller.

| Campaign | Result |
| --- | --- |
| Running | 202; stops at the next guarded node. Journey runs also check before each tool call. In-flight HTTP isn't interrupted (M01), and a refund run finishes its run |
| Stalled | 202; recovers from the checkpoint with cancel set, reaching the guard |
| Awaiting approval | 409 `awaiting_approval`. Nothing is running, and rejecting the approval ends it |
| Already cancelled | 202 |
| Otherwise finished | 409 `campaign_finished` |

A cancel that lands after `consume` leaves the approval spent and the repair unrun.

**Restart.** Checkpoints and approvals are durable; the job registry isn't. A paused
campaign is unaffected. A campaign that was running reads `running` / `stalled` until its
owner resumes it. Nothing restarts it unasked, because a recovered node can repeat a
model call.

**Bounds.** Bodies are limited to 64 KiB, or a capsule's 2,000,000 bytes plus framing on
import, before parsing. Event pages are at most 200. Artifact reads are bounded and
digest-verified by M04.

## What leaves the server

Graph state is never returned directly: `provider`, `limits` and baselines stay inside.
Credentials stay in `ApiConfig.services`. Event summaries, error messages and proposals
pass through `Redactor`, and a test crawls every view for the key and the provider
endpoint. Redaction is pattern-based and is defence in depth (M06). Proposal text is
model output: untrusted data, to be rendered as data. An approval's `action` isn't
redacted, because it must match its digest exactly. Run evidence comes from the
synthetic world and is returned as recorded.

## Running it

```text
GHOSTLAB_AUTH_MODE=local_dev python -m ghostlab.api --port 8787
```

One process only. Inference is disabled there: creating a campaign is a 403
`inference_not_authorized`, and reads, capsule import and replay work.

`tests/api/fixture_server.py` serves the same API with scripted replies, for interface
work. `/v1/session` then reports `inference: "fixture"`, and an interface must show that:
those replies are checked-in fixtures, not a model.

## Validation

See the PR description for commands and actual results. Tests use real M04 SQLite
stores, the real M01 adapter over `httpx.MockTransport` fixtures, the real worlds,
verifier, approvals and capsules, and HTTP through the real middleware and worker
threads. No test makes a network request or calls a model.

## Gaps and requests

Deployment gates, all open:

- Production authentication and a real `SessionAdapter`.
- Membership-backed `ApproverAuthority` and production world bindings.
- Multi-process workers: the job registry is in memory, and SQLite is single-coordinator.
- A live M01 compatibility report before any `LiveInferenceAuthorization`.

To M05 (each is small, and none blocks this branch):

1. `_await_approval` and `_consume` have no cancellation exit. Call `_guard` after the
   interrupt, and before `approvals.consume`. M07 refuses cancel while paused until then,
   because resuming with cancel set would spend an approved action's single use first.
2. `_snapshot` sets `paused` from `snapshot.next`, so `record()` reports any running graph
   as `awaiting_approval`. Use `snapshot.interrupts`, or `state["status"]` in `record()`.
3. An exception escaping `graph.invoke` (`ApprovalDenied` in `_request_repair`,
   `CampaignSettingsChanged` in a node) leaves the checkpoint `running`. M07 shows it as
   `stalled` with `job.error`; a terminal status would be better.
4. `Services.on_node` is documented as test fault injection, and M07 now relies on it to
   know the first checkpoint exists. Either bless it or split `create()` from `run()`.
5. `record()` needs a registered driver, so a campaign whose world stops being runnable
   reads as a 403 rather than a record.
6. `_recorded_run` returns the repair for any `experiment_id`. M07 checks this itself.
7. `capsule_exported` and `replay_completed` are contract event kinds that nothing emits,
   so capsule actions aren't in the event log.

To M04:

1. List approvals by project and status: a reviewer can't discover pending approvals, and
   gets an id from its owner or a campaign view.
2. List campaigns by project and owner: a client must keep its campaign ids, or re-send
   its create request.
3. Persist events and tasks; they live in graph state, so reads go through a checkpoint.

To M00:

1. Contracts for the replay result and the repair assessment, which M07 defines today.
2. `GHOSTLAB_AUTH_MODE` and `GHOSTLAB_DEPLOYMENT` in `.env.example`.
3. `src/ghostlab/api/openapi.v1.json text eol=lf` in `.gitattributes`. The drift check
   normalizes line endings until then.
4. M07 needs both the `service` and `orchestration` extras. A combined extra would say so.

To M08: reach the API through a same-origin proxy, generate types from
`openapi.v1.json`, and show `auth_mode`, `production_authenticated` and `inference`. The
document embeds no examples; M00's published specs and submission are instead driven
through the real routes by a test.

Not added: other worlds, the model-driven Analyst, a campaign list route and event
streaming. Polling is the event interface, and no model-token streaming is assumed.
